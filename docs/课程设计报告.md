# **1 设计目的**

面向对象程序设计课程设计》是虚拟现实技术专业集中实践教学环节之一。本次课程设计以"租书店管理系统"为案例，要求学生在完成 C++ 基础语法学习后，综合运用类与对象、封装、继承、虚函数、多态、结构体数组、文件读写和分文件编程等知识，完成一个可以编译运行、可以保存数据、可以进行角色权限控制的控制台应用程序。

通过本项目训练，学生应能够理解从需求分析、系统设计、编码实现、调试测试到报告撰写和答辩展示的完整项目开发流程；能够把课堂上的零散语法知识转化为一个结构清晰、功能完整的小型软件系统；能够掌握使用头文件和源文件组织工程、使用 CSV 文件进行数据持久化、使用父类指针和虚函数体现多态等核心能力。

# **2 设计要求**

开发语言与环境：使用 C++ 语言开发，建议采用 Dev-C++、Code::Blocks 或 VS Code + MinGW 等 C++ 编译环境；项目以 Windows 控制台交互方式运行。

工程结构要求：采用分文件编程方式，类声明放在 include 目录，类实现放在 src 目录，主流程放在 main.cpp 中，数据文件放在 datas 目录。

面向对象要求：至少包含一个抽象父类 UserBase，并派生 Admin、Staff、Member 三个角色类；通过纯虚函数 showMenu() 和 getRoleType() 体现继承与多态。

功能完整性要求：系统需实现角色登录、管理员/工作人员/会员差异化菜单、书籍维护、会员管理、租借/归还、租金计算、逾期查询、保存和读取 CSV 文件等功能。

数据存储要求：本课程设计采用本地 CSV 文件进行数据保存与读取，不引入外部数据服务、企业级分层框架或窗口界面技术；所有数据均通过 datas/user.csv、datas/book.csv、datas/category.csv、datas/member.csv 和 datas/rental.csv 等文件保存。

代码规范要求：命名清晰、注释适当、菜单提示明确、关键输入有基本合法性检查，能够处理无数据、文件不存在、查询失败等常见情况。

# **3 设计主要内容**

本系统是一个基于 C++ 控制台的租书店管理系统，主要围绕"用户角色权限管理"和"书籍租借管理"两条主线展开。系统启动后首先读取本地 CSV 文件中的书籍和用户数据，用户选择管理员、工作人员或会员身份并输入账号密码，登录成功后进入对应角色菜单。不同角色拥有不同权限：管理员拥有最高权限，工作人员拥有书籍管理和租借管理权限，会员仅能查看书籍、租借和归还书籍。

系统管理的数据以书籍信息、会员信息和租借记录为核心。书籍信息包含书号、书名、作者、出版社、价格、库存和分类；会员信息包含账号、密码、姓名、电话和注册日期；租借记录包含记录ID、书号、会员账号、租借日期、归还日期、租金和逾期费用。系统在租借时自动检查库存并更新，归还时计算租金和逾期费用。管理员执行保存功能后，系统把内存中的数据写入相应的 CSV 文件；程序再次启动时从该文件读取数据，实现数据持久化。

## **4.2 需求分析**

（1）功能性需求

用户登录与权限验证：系统提供管理员、工作人员、会员三类登录入口，根据角色序号、账号和密码完成身份验证。

角色菜单管理：不同角色登录后显示不同菜单。管理员可进行书籍管理、会员管理、租借管理、逾期查询、数据保存；工作人员可进行书籍查看、租借管理、归还管理、逾期查询；会员只能查看书籍、租借书籍、归还书籍、查看个人租借记录。

书籍维护：支持书籍的添加、修改、删除、查询和查看所有书籍。书籍信息包括书号、书名、作者、出版社、价格、库存和分类ID。

会员管理：支持会员的添加、修改、删除、查询和查看所有会员。会员信息包括账号、密码、姓名、电话和注册日期。

租借/归还：会员租借书籍时系统检查库存，创建租借记录并减少库存；归还书籍时更新归还日期并计算费用。

租金计算：根据租借天数和书籍价格计算租金（简化实现：每天租金为书籍价格的1%）。

逾期查询：查询当前日期前未归还的租借记录，标记为逾期。

数据保存与读取：系统启动时读取所有 CSV 文件，管理员可将当前数据保存到 CSV 文件，实现重启后数据不丢失。

（2）非功能性需求

易用性：菜单文字清晰，操作步骤简明，错误输入给出提示，运行结果便于在控制台查看。

可靠性：文件不存在时程序能正常启动；无数据时查询、修改、删除功能应给出提示，不发生异常退出。

可维护性：工程目录清晰，头文件和源文件分离，用户角色类与业务管理类职责明确，便于后续扩展。

适配性：考虑 Windows 控制台中文显示问题，使用 SetConsoleOutputCP(65001) 和 SetConsoleCP(65001) 设置 UTF-8 编码。

## **4.3 系统总体设计**

本系统采用"主函数交互控制 + 角色类 + 业务管理类 + CSV 文件存储"的轻量级控制台项目结构。主函数负责登录流程、菜单循环和功能分发；UserBase 及其派生类负责不同角色的身份与菜单；BookManager、MemberManager、RentalManager 分别负责书籍、会员和租借记录的增删改查及文件读写；datas 目录负责保存所有数据。

系统运行流程为：程序启动后设置控制台编码并初始化用户文件；创建各管理对象并读取相应 CSV 文件；用户选择角色并输入账号密码；验证成功后将 UserBase 指针绑定到对应子类对象；程序通过 user->showMenu() 展示角色菜单，通过 user->getRoleType() 判断权限并调用相应管理类的业务函数；用户退出当前账号后可重新登录其他角色。

## **4.8 问题解决**

问题一：控制台中文显示乱码。

解决方案：在 main.cpp 中包含 windows.h，并在 main 函数开始处调用 SetConsoleOutputCP(65001) 和 SetConsoleCP(65001)，统一控制台输入输出编码。

问题二：分文件编程时出现 undefined reference 等链接错误。

解决方案：检查编译命令是否把 src 目录下的 UserBase.cpp、Admin.cpp、Staff.cpp、Member.cpp、BookManager.cpp、MemberManager.cpp、RentalManager.cpp 全部加入编译，使用命令 `g++ -o main.exe main.cpp src/*.cpp -Iinclude` 一次性编译所有源文件。

问题三：首次运行时找不到 CSV 数据文件。

解决方案：读取文件时判断文件是否存在，不存在则直接返回空数据；保存数据时检查 datas 目录是否存在，不存在则自动创建。

问题四：会员角色不应查看其他会员的租借记录。

解决方案：会员登录成功后使用当前登录账号作为会员ID参数，调用 showMemberRecords(loginMemberId)，避免会员查询他人租借记录。

问题五：租借时库存不足的处理。

解决方案：在执行租借操作前检查书籍库存是否大于0，如果库存为0则提示"库存不足，暂不可借"，避免出现负库存。

# **5 设计体会**

本次面向对象程序设计课程设计以"租书店管理系统"为题目，从需求分析、系统设计到编码实现、调试测试，我经历了一个完整的软件开发流程。回顾整个课程设计过程，我有以下几方面的心得体会。

**一、对面向对象知识的综合运用体会**

在课堂上学习 C++ 的类与对象、封装、继承、虚函数和多态时，每个知识点都是独立学习的，感觉并不难理解。但真正要将这些知识综合运用到一个完整项目中时，才发现其中的挑战。本次课程设计要求设计一个抽象父类 UserBase，并派生出 Admin、Staff、Member 三个角色类，通过纯虚函数 showMenu() 和 getRoleType() 体现多态。在实现过程中，我深刻理解了为什么需要纯虚函数——它强制每个子类必须实现自己的菜单展示逻辑，从而保证不同角色登录后能看到差异化的功能菜单。在 main.cpp 中使用 UserBase 指针指向不同子类对象时，调用 showMenu() 会根据实际对象类型执行对应的菜单函数，这就是运行时多态的核心体现，让我对"父类指针可以指向子类对象，调用的是子类重写的函数"这句话有了真正的理解。

**二、对系统架构设计的体会**

本次课程设计的系统比课堂练习复杂得多，涉及书籍管理、会员管理、租借管理三大业务模块。我最初的想法是把所有功能都写在 main.cpp 中，但很快发现这样会导致代码量过大、逻辑混乱、难以维护。于是我把业务逻辑拆分到 BookManager、MemberManager、RentalManager 三个管理类中，main.cpp 只负责登录流程、菜单循环和功能分发。这种职责分离的设计让代码结构变得清晰，每个类只关注自己的业务逻辑，修改某个模块时不会影响到其他模块。同时，我也认识到好的架构设计需要在编码之前就做好规划，而不是边写边改。

**三、对数据持久化的体会**

CSV 文件存储是本次课程设计的另一个重要环节。系统启动时需要从 CSV 文件读取数据，退出时需要将内存中的数据保存回文件。在实现过程中，我学习了使用 ifstream、ofstream 进行文件读写，使用 getline 和 stringstream 进行字符串分割，使用 stof、stoi 进行类型转换。这些操作看似简单，但在实际编码中需要注意很多细节，比如 CSV 文件中逗号的处理、空字段的判断、文件编码的设置等。通过这个过程，我理解了数据持久化的本质就是将内存中的对象状态序列化为文本文件，读取时再反序列化回内存对象。

**四、对解决问题能力的提升体会**

在开发过程中，我遇到了不少问题。比如控制台中文显示乱码，通过设置 UTF-8 编码解决；分文件编程时出现链接错误，通过检查编译命令确保所有源文件都被编译解决；首次运行时 CSV 文件不存在导致程序异常，通过添加文件存在性检查解决。每个问题的解决都让我积累了调试经验。特别是当程序出现 bug 时，我学会了通过添加 cout 输出语句来追踪程序执行流程，定位问题所在。这种系统化的调试思路比盲目猜测要高效得多。

**五、对功能不足的认识与未来展望**

目前的系统虽然实现了基本功能，但仍存在一些不足。首先，租金计算逻辑比较简单，仅按天数和书价的固定比例计算，实际场景中可能需要考虑会员等级折扣、节假日优惠等因素。其次，系统没有实现并发控制，不适合多用户同时操作。再次，系统缺少数据校验机制，比如书籍价格不能为负数、会员电话号码格式校验等。未来如果有机会继续完善，可以考虑增加会员等级体系、租借排行榜、逾期罚款阶梯计算、数据备份与恢复等功能，也可以尝试使用 SQLite 数据库替代 CSV 文件存储，提升数据管理能力。

**六、总结**

通过本次课程设计，我不仅巩固了 C++ 面向对象编程的知识，还锻炼了系统设计、模块划分、文件操作和调试测试的能力。整个过程让我认识到，写代码不只是让程序能跑起来，更要让代码结构清晰、易于维护。这次经历为我今后学习更复杂的软件开发打下了良好的基础，也让我对面向对象编程思想有了更深入的理解。
